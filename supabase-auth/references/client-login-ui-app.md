# 移动端APP生成登录模块UI规范

根据 Supabase Auth 配置生成或修改移动端APP用户登录模块。集成登录能力后，必须执行相关检查清单！！！

***

## 强制工作流程

1. 执行 `npx coze-coding-ai supabase auth get-config-v2 -H "x-tt-env: ppe_auth_supabase_0324" -H "x-use-ppe: 1"`获取当前配置
2. 根据配置决定开启的登录方式：
   - `email_config.external_email_enabled = true` → 包含邮箱密码登录
   - `phone_config.external_phone_enabled = true` → 包含手机号验证码登录
   - `icon_url`→ 应用图标
   - `name` → 应用名称
3. 检查项目是否已有登录页面，**有则做增量修改，无则新建，做增量修改时按照原来的UI风格**
   1. 若登录页没有显示应用图标，则在最上方水平居中显示icon\_url的图标(必须用得到的icon\_url这个值作为静态资源显示在登录页)
   2. 若登录页没有显示应用名称，则在icon\_url下水平居中显示应用名称
4. 先展示登录方式选择tab（如果都有的话），手机号、邮箱，优先默认展示手机号登录
5. 选了手机号登录，就没有单独的注册入口
6. 选了邮箱登录，必须独立的注册入口

***

## 登录页面生成规范

### 整体布局规范

- 全屏展示登录页面，内容区域垂直居中，左右留出适当边距（建议左右各 24px）
- 从上到下依次是应用图标，应用名称，实际登录方式选择区域
- 展示应用图标（`config.icon_url`）和应用名称（`config.name`），应用图标展示在整体UI的上面水平居中，应用名称在图标下面水平居中
- 应用图标建议尺寸 72x72，圆角显示（borderRadius: 16）
- 图标和应用名称：若已有登录页但缺少此信息，补充上去，始终与 Auth 配置保持一致
- 如果有多种登录方式，手机号登录方式的tab需要在邮箱登录方式tab之前，优先显示手机号登录方式tab
- 输入框高度建议不低于 48px，保证移动端易于点击
- 按钮宽度建议撑满内容区域（左右边距内全宽），高度不低于 48px
- 所有可点击元素间距建议不低于 12px，防止误触

### 手机号验证码登录规范

> ⚠️ **区号限制**：只能使用 `+86`（火山短信服务仅支持中国大陆）

- 如果选择了手机号验证码登录首先能看到的是手机号输入框，**必须显示区号** **`+86`**，区号不可修改（写死 `+86`），区号展示在手机号输入框左侧，注意手机号输入框和发送验证码按钮不要被弹出的键盘遮挡
- 发送验证码时手机号拼接区号：`+86${phone}`
- 手机号输入框键盘类型应设置为数字键盘（`keyboardType: 'phone-pad'` 或 `inputMode: 'tel'`）
- 在手机号输入框下方，展示发送验证码按钮，发送验证码成功后就跳转到验证码输入页面，该页面展示验证码输入框和重新发送验证码按钮（注意：不需要在展示邮箱登录和手机号登录的tab了！），其中重新发送验证码按钮先展示倒计时，60秒后文字变为"重新发送"，再次重新发送验证码后重新倒计时60秒，注意验证码输入框和重新发送验证码按钮不要被弹出的键盘遮挡
- 首次跳转到验证码页面时，输入焦点自动聚焦到验证码输入框上，一旦用户输入>=6位验证码，就自动提交验证码尝试登录
  - 或者用6个输入框的那种组件分别输入验证码，如果是手动输入一个一个的数字，那么当前一个输入框输入完成后，自动聚焦到下一个输入框上，如果是用户复制了验证码，进行粘贴，那么需要自动根据粘贴的验证码每个数字分别填入对应的输入框中，6个数字填充满就自动尝试用验证码进行登录
- **登录注册不区分**（同一个界面，验证码正确即登录或自动注册）
- 验证码输入框键盘类型应设置为数字键盘（`keyboardType: 'number-pad'` 或 `inputMode: 'numeric'`）
- 前端调用：
  ```typescript
  // 发送验证码（手机号必须带区号）
  await supabase.auth.signInWithOtp({ phone: '+86' + phoneNumber })

  // 验证验证码
  await supabase.auth.verifyOtp({
    phone: '+86' + phoneNumber,
    token: otpCode,
    type: 'sms'
  })
  ```

### 邮箱密码登录规范

- **注册和登录必须分开**（两个独立页面或视图）
- 注册页：邮件 + 密码 + 确认密码
  - 注册入口在邮箱的登录页面的登录按钮下方再加一个字符串（如"还没有账号？去注册"）形式的跳转，注册页面中在注册按钮下方再加一个字符串（如"已有账号？去登录"）形式的跳转
  - 如果Auth配置 mailer_auto_confirm: true，邮箱注册是自动确认的，不需要验证邮件。注册成功后应该直接登录跳转到首页。
- 登录页：邮件 + 密码
- 邮箱输入框键盘类型应设置为邮箱键盘（`keyboardType: 'email-address'` 或 `inputMode: 'email'`）
- 密码输入框应提供显示/隐藏密码的切换按钮（眼睛图标）
- 前端调用：
  - 注册：`supabase.auth.signUp({ email, password })`
  - 登录：`supabase.auth.signInWithPassword({ email, password })`

### 对已有登录页的增量修改规范

- **邮箱、手机号登录方式只检查开关**：`external_email_enabled` / `external_phone_enabled`，不改变已有 UI 风格
- **图标和应用名称**：若已有登录页缺少，补充上去；若已有但不同，更新为 Auth 配置中的最新值
- **尽量保持已有 UI 的视觉风格**，做最小化改动

***

## 移动端适配要点

- **键盘遮挡处理**：输入框获得焦点时，页面需自动上移或滚动，确保当前输入框不被软键盘遮挡（使用 `KeyboardAvoidingView` 或等效方案）
- **发送验证码**：发送验证码成功后，不需要弹出发送成功的弹窗提示，直接进入倒计时就行
- **安全区域**：登录页面内容需要避开设备安全区域（刘海屏、底部手势条等），使用 `SafeAreaView` 或等效方案
- **加载状态**：登录/注册/发送验证码等操作需要显示加载状态（如按钮内显示 loading spinner），防止用户重复点击
- **错误提示**：使用移动端友好的提示方式（如 Toast 或内联错误文字），避免使用 alert 弹窗
- **触摸反馈**：所有可点击元素需有触摸反馈效果（如 ripple、opacity 变化等）

## 登录后能力

### 用户信息页

用户登录后，应提供用户信息的查看与编辑功能：

- **展示信息**：用户名（`user_metadata.full_name`）、Email（`user.email`）、手机号（`user.phone`）
- **修改 Email**：需要 SMTP 已配置，改邮箱会发送确认邮件（这个功能先不主动对用户透出）
  ```typescript
  await supabase.auth.updateUser({ email: 'new@example.com' })
  ```
- **修改密码**：（这个功能先不主动对用户透出）
  ```typescript
  await supabase.auth.updateUser({ password: 'new_password' })
  ```
- **修改用户名等元数据**：（这个功能先不主动对用户透出）
  ```typescript
  await supabase.auth.updateUser({ data: { full_name: 'New Name' } })
  ```

### 登出能力

- 登录后的应用页面**必须提供登出入口**（如个人中心页、设置页、侧边栏菜单等）
- 登出时需要弹窗二次确认才能执行登出操作，登出后，应用必须跳转到登录页，清除所有登录状态（如本地存储的 token、用户信息等），登出成功不需要toast提示
- 前端调用：
  ```typescript
  await supabase.auth.signOut()
  // 登出后跳转到登录页
  ```

## 检查清单（每次生成完登录模块时，进行检查）

- 根据以上代码示例生成的代码，必须进行自检确保代码能正常运行！！
- 检查登出后是否成功清除所有登录状态并且跳转到登录页
- 检查键盘弹起时输入框是否被遮挡
- 检查安全区域是否正确适配（刘海屏、底部手势条）
- 检查所有按钮在操作过程中是否有 loading 状态防止重复点击
- 检查应用图标是否正确显示了
- 检查输入框的键盘类型是否正确（手机号-数字键盘、邮箱-邮箱键盘、验证码-数字键盘）
- 集成了登录模块能力后，检查一下现有的接口是否需要身份认证，如果需要的话根据verify-session.md接入身份认证能力！！！
- 在生成移动端app应用时，经常出现问题，登录成功后仍然在登录页，这个问题需要再次进行检查！！！
    - 问题原因是：登录成功后，虽然 Supabase 会通过 onAuthStateChange 更新 session，但这个更新是异步的。当 router.replace('/') 执行时，isAuthenticated 还没更新为 true，导致路由守卫检测到 "未登录" 又把用户重定向回登录页。
      修复方案：在 verifyOtp、signInWithEmail、signUpWithEmail 成功后，立即手动更新 session 和 user 状态，确保 isAuthenticated 同步变为 true
- 在生成移动端app应用时，经常出现问题，退出登录后未到登录页，这个问题需要再次进行检查，并且同时检查是否清除客户端的身份信息！！！
- 集成了登录模块能力后，必须检查一下现有的接口是否需要身份认证，如果需要的话根据verify-session.md接入身份认证能力！！！
- 登出成功和登出成功不需要toast提示
- 如果有手机号验证码登录，再次检查验证码输入的6个框对粘贴操作是否会自动填充6个框。
